# Collection Card — ร่างระบบ (Draft v0.1)

> เว็บฐานข้อมูลราคาการ์ดสะสม (One Piece TCG / Pokémon TCG)
> ประกอบด้วย **หน้าเว็บสาธารณะ** (ให้คนทั่วไปดูการ์ด/ราคา) และ **แดชบอร์ดหลังบ้าน** (ให้แอดมินเพิ่มการ์ด + อัปเดตราคา)
> เป้าหมายระยะยาว: ให้ผู้ใช้สมัครเข้ามาเก็บ **คอลเลกชันของตัวเอง**

---

## 1. ภาพรวม

```
┌─────────────────┐        ┌──────────────┐        ┌──────────────────┐
│  Public Site    │◀──────▶│   API / DB   │◀──────▶│ Admin Dashboard  │
│  (SEO + user)   │        │  Postgres    │        │ (CRUD + ราคา)    │
└─────────────────┘        └──────┬───────┘        └──────────────────┘
                                  │
                           ┌──────▼───────┐
                           │ Price Worker │  cron: snapshot ราคารายวัน
                           └──────────────┘
```

**Stack ที่แนะนำ**

| ส่วน | เลือก | เหตุผล |
|---|---|---|
| Framework | Next.js (App Router) + TypeScript | หน้า public ต้องการ SSR/SEO, แดชบอร์ดใช้ codebase เดียวกันได้ (`/admin`) |
| DB + Auth + Storage | Supabase (Postgres) | ได้ Auth, Row Level Security, Storage รูปการ์ด, cron ครบในตัว ลดงาน infra |
| ORM | Drizzle หรือ Prisma | schema เป็นโค้ด migrate ง่าย |
| UI | Tailwind + shadcn/ui | ตารางแอดมินและฟอร์มเยอะ ประหยัดเวลา |
| กราฟราคา | Recharts / visx | sparkline + กราฟประวัติราคา |
| Deploy | Vercel + Supabase | ฟรีพอสำหรับเฟสแรก |

ทางเลือก: ถ้าอยากคุมเองทั้งหมด ใช้ Next.js + Postgres (Neon/Railway) + Auth.js แทน Supabase

## 2. โครงสร้างข้อมูล (สำคัญที่สุด — ออกแบบพลาดตรงนี้แก้ทีหลังเจ็บ)

### หัวใจ 3 ข้อที่คนมักพลาด

1. **ราคาไม่ได้ผูกกับ "การ์ด" แต่ผูกกับ "เวอร์ชันการ์ด + สภาพ"**
   การ์ดใบเดียวกันมีทั้ง Normal / Parallel / Alt-Art / Manga Rare ราคาต่างกันได้ 10–100 เท่า
2. **ภาษาเป็นอีกแกนหนึ่ง** — ชุดเดียวกันฉบับ JP กับ EN คนละราคา คนละตลาด
3. **การ์ดเกรด (PSA/BGS) คือตลาดแยก** — เก็บ `grading_company` + `grade` เป็นคอลัมน์ nullable

### ตาราง

```sql
games            (id, slug, name_th, name_en, logo_url, sort_order)
sets             (id, game_id, code, name_th, name_en, language, release_date,
                  total_cards, symbol_url, cover_url)
cards            (id, set_id, number, name_th, name_en, rarity, card_type,
                  color, artist, image_url)
card_variants    (id, card_id, variant_type, is_foil, image_url,
                  UNIQUE(card_id, variant_type))          -- ราคาผูกที่นี่

price_points     (id, variant_id, condition, grading_company, grade,
                  source, currency, price, recorded_at)   -- time series (append-only)
price_current    (variant_id, condition, price_thb, price_src, change_24h,
                  change_7d, change_30d, updated_at)      -- materialized view / cache
fx_rates         (currency, rate_thb, fetched_at)

users            (id, email, display_name, username, avatar_url, role)
collections      (id, user_id, name, is_public, slug)
collection_items (id, collection_id, variant_id, condition, quantity,
                  acquired_price, acquired_at, note)
wishlist_items   (id, user_id, variant_id, target_price, notify_channel)
audit_logs       (id, actor_id, action, entity, entity_id, before, after, at)
```

**Unique key กันข้อมูลซ้ำ:** `game + set.code + card.number + variant_type + set.language`

**Enum ที่ควรกำหนดตั้งแต่แรก**

- `condition`: `NM | LP | MP | HP | DMG | SEALED`
- `variant_type`: `normal | parallel | alt_art | manga | full_art | promo | reprint`
- `source`: `manual | tcgplayer | cardmarket | yahoo_jp | shopee | facebook | local_shop`

## 3. หน้าเว็บสาธารณะ (Routes)

```
/                       เลือกเกม → [One Piece] [Pokémon]
/g/one-piece            รายการชุดทั้งหมด (ชุดใหม่ขึ้นก่อน)
/g/one-piece/op-01      การ์ดในชุด — filter: rarity / ราคา / สี / ค้นหา
/card/[slug]            รายละเอียดการ์ด + กราฟราคา + เลือก variant & condition
/search?q=              ค้นหารวมทุกเกม
/movers                 การ์ดราคาขึ้น/ลงแรงสุด 7 วัน       ← ตัวดึงคนกลับมาซ้ำ
/u/[username]           คอลเลกชันสาธารณะ                   (เฟส 2)
/me/collection          คอลเลกชันของฉัน                    (เฟส 2)
```

### หน้าเลือกเกม (`/`)

การ์ดใหญ่ 2 ใบ One Piece / Pokémon พร้อมตัวเลข "1,240 ใบ · 14 ชุด · อัปเดต 2 ชม.ที่แล้ว"
ตัวเลขความสดของข้อมูลคือสิ่งที่สร้างความน่าเชื่อถือ ให้แสดงชัด ๆ

### หน้ารายการชุด (`/g/one-piece`)

Grid ปกชุด + code + วันวางจำหน่าย + จำนวนการ์ด + มูลค่าเฉลี่ยของชุด · มี toggle JP / EN

### หน้าการ์ดในชุด

Grid รูปการ์ด แสดงราคาปัจจุบันมุมล่าง + ลูกศรขึ้น/ลง
Filter: rarity, ช่วงราคา, variant, "มี/ยังไม่มีในคอลเลกชันฉัน" (เมื่อล็อกอิน)
Sort: เลขการ์ด / ราคา / ราคาที่เปลี่ยนแปลง

### หน้าการ์ด (`/card/[slug]`)

- รูปใหญ่ + zoom
- ตารางราคาแยกตาม variant × condition
- กราฟราคาย้อนหลัง 7D / 1M / 3M / 1Y
- ปุ่ม **+ เพิ่มเข้าคอลเลกชัน** และ **♡ ใส่ Wishlist**
- การ์ดใบอื่นในชุดเดียวกัน (internal link ช่วย SEO)

## 4. แดชบอร์ดแอดมิน

| เมนู | ทำอะไร |
|---|---|
| ภาพรวม | จำนวนการ์ด/ชุด, ราคาที่ไม่อัปเดตเกิน 7 วัน, งาน sync ที่ล้มเหลว, การ์ดที่ราคาขยับแรง |
| เกม & ชุด | เพิ่ม/แก้เกม, เพิ่มชุดใหม่ (code, วันวางจำหน่าย, จำนวนการ์ด) |
| การ์ด | ตารางค้นหา/แก้ไข + **นำเข้า CSV ทีละชุด** + อัปโหลดรูปหลายไฟล์ |
| **อัปเดตราคา** | ตารางแบบ spreadsheet — พิมพ์ตัวเลข กด Enter ลงแถวถัดไป บันทึกอัตโนมัติ |
| ประวัติ & Log | ใครแก้อะไรเมื่อไหร่ ย้อนดูราคาเก่า |
| แหล่งราคา | ตั้งค่า source, อัตราแลกเปลี่ยน, ตารางเวลา cron |
| ผู้ใช้ | ดูผู้ใช้, ตั้ง role, ระงับบัญชี |

> **หน้าที่ต้องออกแบบให้ดีที่สุดคือหน้าอัปเดตราคา** เพราะเป็นหน้าที่จะแตะทุกวัน
> ต้องทำงานด้วยคีย์บอร์ดล้วนได้: `↑↓` เลื่อนแถว, `Enter` บันทึก + ลงแถวถัดไป, `Tab` ข้าม condition
> และรองรับการวางข้อมูลจาก Excel ทีเดียวทั้งคอลัมน์

### การอัปเดตราคา 3 ระดับ (ทำไล่ตามลำดับ)

1. **Manual** — พิมพ์เอง (เฟส 1, ใช้งานได้จริงทันที)
2. **Import** — อัปโหลด CSV / วางจาก Excel ทั้งชุด (เฟส 1.5)
3. **Auto** — worker ดึงตามรอบ แล้วให้แอดมิน "อนุมัติ" ก่อนเผยแพร่ (เฟส 4)

ทุกครั้งที่บันทึกราคา **ให้ insert แถวใหม่ใน `price_points` เสมอ ห้าม update ทับ** — ประวัติราคาคือสินทรัพย์

## 5. Roadmap

| เฟส | ขอบเขต | ผลลัพธ์ |
|---|---|---|
| **P0** (2–3 สัปดาห์) | Schema, Admin CRUD, ราคา manual, หน้า public อ่านอย่างเดียว | เว็บใช้งานได้จริง มีข้อมูล 1–2 ชุด |
| **P1** | กราฟราคาย้อนหลัง, ค้นหา, filter, รูปบน CDN, SEO/OG image | เริ่มมี traffic จาก Google |
| **P2** | Auth + คอลเลกชันของฉัน + % ความสมบูรณ์ของชุด + มูลค่าพอร์ต | ผู้ใช้มีเหตุผลให้สมัคร |
| **P3** | Wishlist + แจ้งเตือนราคา (LINE) + หน้าคอลเลกชันสาธารณะแชร์ได้ | ผู้ใช้กลับมาซ้ำ + แชร์ต่อ |
| **P4** | ดึงราคาอัตโนมัติ, จับคู่แลกการ์ด, marketplace | เป็นแพลตฟอร์ม |

## 6. สิ่งที่แนะนำให้ทำเพิ่ม (เรียงตามความคุ้ม)

### ทำแน่นอน

1. **% ความสมบูรณ์ของชุด** — "คุณมี 42/121 ใบ (35%)" พร้อมแถบ progress
   นี่คือกลไกเสพติดของนักสะสม และเป็นแรงจูงใจอันดับ 1 ที่ทำให้คนยอมกรอกข้อมูลลงเว็บคุณ
2. **มูลค่าพอร์ตย้อนหลัง + กำไร/ขาดทุน** — เทียบราคาที่ซื้อกับราคาปัจจุบัน
   เปลี่ยนเว็บจาก "ฐานข้อมูล" เป็น "แอปที่ต้องเปิดทุกวัน"
3. **เก็บ snapshot ราคาทุกวันตั้งแต่วันแรก** — ข้อมูลย้อนหลังซื้อไม่ได้ ยิ่งเก็บเร็วยิ่งเป็นกำแพงกันคู่แข่ง
4. **SEO รายใบ** — คนค้น "ราคาการ์ด OP01-025 ลูฟี่" ทุกวัน หน้า `/card/[slug]` คือช่องทางหาผู้ใช้ที่ถูกที่สุด
   ต้องมี title/description, JSON-LD `Product` + `AggregateOffer`, และ OG image ที่สร้างอัตโนมัติ
5. **Mobile-first** — นักสะสมเปิดดูจากมือถือตอนอยู่หน้าร้านการ์ด ไม่ใช่หน้าคอม
6. **หน้า `/movers`** — เหตุผลให้เข้าเว็บซ้ำแม้ไม่มีอะไรจะทำ

### ทำในเฟส 2–3

7. **เพิ่มการ์ดด้วยการสแกน** — ถ่ายรูปแล้ว OCR เลขการ์ดมุมล่างซ้าย
   จุดนี้คือที่ที่ผู้ใช้เลิกกลางคัน ไม่มีใครกรอกการ์ด 300 ใบด้วยมือ ลดแรงเสียดทานตรงนี้ = ได้ผู้ใช้จริง
8. **หน้าคอลเลกชันสาธารณะ + OG image สวย ๆ** — คนเอาไปแชร์กลุ่ม Facebook = โฆษณาฟรี
9. **มุมมองแฟ้มการ์ด (Binder view) 3×3** — ตรงกับพฤติกรรมจริงของนักสะสม และแชร์ง่าย
10. **แจ้งเตือนราคาผ่าน LINE** — ช่องทางที่คนไทยใช้จริง (LINE Messaging API) ได้ผลกว่าอีเมลมาก
11. **จับคู่แลกการ์ด** — "การ์ดที่ฉันมีเกิน × การ์ดที่เขาขาด" เป็นฟีเจอร์ที่ทำให้คนชวนเพื่อนเข้ามาใช้

### เชิงเทคนิค/ธุรกิจที่ต้องคิดล่วงหน้า

12. **ราคาไทย ≠ ราคาสากล** — เก็บหลาย source แล้วแสดงเทียบ ("ตลาดโลก ฿1,200 · ตลาดไทย ฿1,650")
    จุดนี้คือสิ่งที่เว็บต่างประเทศให้ไม่ได้ = ความได้เปรียบของคุณ
13. **ลิขสิทธิ์รูปการ์ด** — รูปการ์ดอย่างเป็นทางการมีลิขสิทธิ์ ควรใช้ความละเอียดต่ำ + ใส่เครดิต
    หรือให้ผู้ใช้อัปโหลดรูปการ์ดของตัวเอง และเตรียมขั้นตอนลบเมื่อถูกร้องขอ
14. **การดึงข้อมูลจากเว็บอื่น** — เคารพ robots.txt, ใส่ rate limit, ตรวจ ToS ของแหล่งข้อมูลก่อนทำ auto-sync
15. **Audit log + soft delete ในแดชบอร์ด** — มีวันที่ลบผิด ต้องกู้ได้
16. **ตั้งชื่อ slug ให้นิ่งตั้งแต่แรก** — เปลี่ยน URL ทีหลังเสีย SEO ที่สะสมมา

### ยังไม่ต้องทำตอนนี้

- ระบบซื้อขาย/ชำระเงินในเว็บ (ภาระ compliance สูง รอจนมีผู้ใช้จริงก่อน)
- แอปมือถือ native (PWA พอสำหรับ 2 ปีแรก)
- รองรับเกมที่ 3–4 (ออกแบบ schema ให้รองรับไว้ แต่ยังไม่ต้องเปิด)

## 7. ขั้นตอนถัดไป

1. ยืนยัน stack (Next.js + Supabase หรืออื่น)
2. ลง schema จริงตามข้อ 2 แล้ว seed ข้อมูล **1 ชุด** (แนะนำ OP-01) ให้ครบทุกใบ
3. ทำหน้าอัปเดตราคาในแดชบอร์ดให้ใช้งานได้ก่อนหน้าอื่น — ถ้ากรอกข้อมูลไม่ไหว โปรเจกต์จะตายตรงนี้
4. เปิดหน้า public แบบอ่านอย่างเดียว แล้วเอาไปโพสต์กลุ่มนักสะสมเพื่อขอ feedback
5. ค่อยเปิดระบบสมาชิก
