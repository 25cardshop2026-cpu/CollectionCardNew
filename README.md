# Collection Card

เว็บฐานข้อมูลราคาการ์ดสะสม **One Piece** และ **Pokémon** พร้อมแดชบอร์ดหลังบ้านสำหรับเพิ่มการ์ดและอัปเดตราคา

> เฟส **P0** — หน้าเว็บสาธารณะและแดชบอร์ดใช้งานได้แล้ว แต่ยังทำงานบนข้อมูลตัวอย่างในหน่วยความจำ
> แผนเต็มและเหตุผลของการออกแบบอยู่ใน [`docs/PLAN.md`](docs/PLAN.md)

## เริ่มใช้งาน

```bash
npm install
npm run dev
```

เปิด http://localhost:3000

## หน้าที่มีแล้ว

หน้าเว็บสาธารณะรองรับสองภาษา ทุก URL มี prefix ภาษาเสมอ (`/th/...` และ `/en/...`)

| Route | ทำอะไร |
|---|---|
| `/[locale]` | หน้าแลนดิ้ง มีปุ่มเข้าใช้งาน |
| `/[locale]/browse` | เลือกเกม + การ์ดที่ราคาขยับแรง |
| `/[locale]/g/[game]` | รายการชุดของเกมนั้น |
| `/[locale]/g/[game]/[set]` | การ์ดทั้งหมดในชุด พร้อมตัวกรอง rarity และการเรียงลำดับ |
| `/[locale]/card/[slug]` | รายละเอียดการ์ด ราคาแยก variant × สภาพ กราฟย้อนหลัง 90 วัน และ JSON-LD |
| `/[locale]/movers` | การ์ดที่ราคาขยับแรงที่สุดใน 7 วัน |
| `/admin` | ภาพรวม จำนวนการ์ด และราคาที่ค้างอัปเดต |
| `/admin/cards` | จัดการการ์ด — เพิ่ม แก้ ลบ แยกตามชุด |
| `/admin/sets/new` | เพิ่มชุดใหม่ |
| `/admin/prices` | ตารางอัปเดตราคาแบบ spreadsheet ทำงานด้วยคีย์บอร์ดล้วนได้ |

หน้าเว็บสาธารณะกับแดชบอร์ดอ่านเขียนผ่าน `lib/repo.ts` ชุดเดียวกัน และทุกหน้าเป็น dynamic
ของที่เพิ่มหรือแก้ในแดชบอร์ดจึงขึ้นบนหน้าเว็บทันทีที่รีเฟรช

## โครงสร้าง

```
app/          หน้าเว็บทั้งหมด (App Router)
components/   ส่วนประกอบ UI ที่ใช้ซ้ำ
lib/types.ts     รูปร่างของข้อมูลทั้งระบบ
lib/seed.ts      ข้อมูลตั้งต้น + ตัวสร้างราคาย้อนหลังแบบ deterministic
lib/overrides.ts ส่วนต่างที่แอดมินแก้ เก็บลง data/overrides.json
lib/repo.ts      ชั้นเข้าถึงข้อมูลทั้งหมด — จุดเดียวที่ต้องแก้ตอนต่อฐานข้อมูลจริง
lib/actions.ts   Server Actions ของฟอร์มในแดชบอร์ด
docs/PLAN.md     แผนระบบฉบับเต็ม schema roadmap และข้อเสนอแนะ
```

### สองภาษา

- `lib/i18n/th.ts` เป็นต้นแบบของโครงสร้างคำแปล `en.ts` ถูกบังคับด้วย TypeScript ให้มีคีย์ครบเท่ากัน
  ถ้าเพิ่มข้อความใหม่แล้วลืมแปล จะ build ไม่ผ่าน
- `middleware.ts` เดาภาษาจาก `Accept-Language` แล้ว redirect `/` ไป `/th` หรือ `/en`
- ทุกหน้ามี `hreflang` ชี้ไปอีกภาษา เพื่อไม่ให้ Google มองว่าเป็นเนื้อหาซ้ำ
- แดชบอร์ดมี root layout แยกของตัวเองที่ `app/(admin)/` และเป็นภาษาไทยอย่างเดียว
  เพราะเป็นเครื่องมือหลังบ้าน ไม่ต้องทำ SEO

### ข้อมูลถูกเก็บยังไง

สถานะปัจจุบัน = ข้อมูลตั้งต้นใน `seed.ts` + ส่วนต่างใน `data/overrides.json`

เก็บลงไฟล์ ไม่ใช่ตัวแปรในหน่วยความจำ เพราะ Next.js สร้างโมดูลแยกชุดกันต่อ route
ถ้าเก็บในหน่วยความจำ ของที่เพิ่มจะหายทันทีที่ผู้ใช้ย้ายหน้า

## หลักการที่ยึดไว้ตั้งแต่ต้น

1. **ราคาผูกกับ variant + สภาพ ไม่ใช่ผูกกับการ์ด** — การ์ดใบเดียวกัน Normal กับ Alt Art ราคาต่างกันได้ 10–100 เท่า
2. **ภาษาเป็นอีกแกนหนึ่ง** — ชุดเดียวกันฉบับ JP กับ EN เป็นคนละแถวในตาราง `sets`
3. **บันทึกราคาเป็นแถวใหม่เสมอ ไม่เขียนทับ** — ประวัติราคาย้อนหลังซื้อกลับไม่ได้

## ขั้นตอนถัดไป

- [ ] ต่อ Postgres จริง แล้วเขียน adapter ใน `lib/repo.ts` (สัญญาของฟังก์ชันไม่ต้องเปลี่ยน)
- [ ] cron บันทึก snapshot ราคารายวัน
- [ ] รูปการ์ด — ตัดสินใจเรื่องลิขสิทธิ์ก่อน (ดู `docs/PLAN.md` ข้อ 6.13)
- [ ] Auth + คอลเลกชันของผู้ใช้ + % ความสมบูรณ์ของชุด

## ข้อจำกัดที่ต้องรู้

- **แดชบอร์ดแก้ข้อมูลได้เฉพาะตอนรันบนเครื่อง** บนโฮสต์แบบ serverless อย่าง Vercel
  ดิสก์เขียนไม่ได้ แดชบอร์ดจะกลายเป็นอ่านอย่างเดียวและขึ้นแถบแจ้งเตือน
  ต้องต่อฐานข้อมูลจริงก่อนจึงจะแก้ข้อมูลบนเว็บที่ deploy แล้วได้
- **ข้อมูลเป็นตัวอย่าง** ชื่อการ์ดและราคาไม่ใช่ข้อมูลตลาดจริง ใช้เพื่อสาธิตโครงสร้างเท่านั้น
- **`/admin` ยังไม่มีระบบ Auth** ใครที่รู้ URL ก็เข้าได้ ต้องใส่ก่อนเปิดใช้งานจริง
- **ยังไม่มีการยืนยันก่อนลบ** ปุ่มลบทำงานทันที
